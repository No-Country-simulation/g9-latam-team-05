# Arquitectura de Base de Datos y Script DDL

## Descripción del Problema Principal
La gestión financiera personal suele ser fragmentada y carecer de diagnósticos automatizados. El problema principal que resuelve la capa de datos de **Finance AI** es la necesidad de un almacenamiento estructurado, seguro y de alta integridad capaz de soportar operaciones transaccionales concurrentes (registro de gastos, presupuestos y perfiles) y de almacenar de manera persistente el historial de análisis y recomendaciones generadas por los módulos de inteligencia artificial.

---

## Arquitectura y Esquema de Base de Datos
El almacenamiento del sistema se encuentra alojado en Oracle Database bajo el esquema exclusivo **`APP_SPRING_BOOT`**. 

### Decisiones de Diseño y Optimización:
* **Integridad Referencial:** Todas las relaciones críticas entre usuarios, categorías, transacciones, presupuestos e historiales de IA están blindadas mediante claves foráneas con eliminación en cascada (`ON DELETE CASCADE`), asegurando que no queden registros huérfanos si un usuario o análisis es eliminado.
* **Tipos de Datos Optimizados:** Se utilizaron tipos nativos de Oracle como `NUMBER` con precisión definida para montos financieros (`NUMBER(12,2)`), `BINARY_DOUBLE` para cálculos de transacciones de alta precisión, y `CLOB` en la tabla de recomendaciones para almacenar textos extensos generados por la IA.
* **Estrategia de Índices:** Se implementaron índices compuestos y simples en columnas de alta frecuencia de búsqueda y filtrado (como los correos de usuarios, las fechas de transacciones y los identificadores de análisis, entre otros) para garantizar un rendimiento óptimo en las consultas del backend.

---

## Script SQL de Creación del Esquema
A continuación se presenta el script optimizado utilizado para la creación de las tablas, restricciones e índices en el entorno de Oracle Database:

```sql
-- 
-- ===============CREACIÓN DE TABLAS PRINCIPALES=======================
-- 

CREATE TABLE APP_SPRING_BOOT.usuarios (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre VARCHAR2(100) NOT NULL,
    email VARCHAR2(100) NOT NULL CONSTRAINT uk_usuarios_email UNIQUE,
    password_hash VARCHAR2(255) NOT NULL,
    fecha_creacion TIMESTAMP(6) DEFAULT CURRENT_TIMESTAMP NOT NULL
);

CREATE TABLE APP_SPRING_BOOT.categorias (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre VARCHAR2(50) NOT NULL CONSTRAINT uk_categorias_nombre UNIQUE,
    icono VARCHAR2(50),
    color VARCHAR2(7)
);

CREATE TABLE APP_SPRING_BOOT.perfiles_financieros (
    user_id NUMBER PRIMARY KEY,
    ingreso_mensual NUMBER(12,2),
    nivel_endeudamiento NUMBER(5,2),
    frecuencia_ahorro VARCHAR2(20) CHECK (frecuencia_ahorro IN ('Baja', 'Media', 'Alta')),
    fecha_actualizacion TIMESTAMP(6) DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_perfil_usuario FOREIGN KEY (user_id) REFERENCES APP_SPRING_BOOT.usuarios(id) ON DELETE CASCADE
);

CREATE TABLE APP_SPRING_BOOT.presupuestos (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id NUMBER NOT NULL,
    categoria_id NUMBER NOT NULL,
    monto_limite NUMBER(12,2) NOT NULL,
    periodo VARCHAR2(30) NOT NULL,
    CONSTRAINT fk_presupuesto_usuario FOREIGN KEY (user_id) REFERENCES APP_SPRING_BOOT.usuarios(id) ON DELETE CASCADE,
    CONSTRAINT fk_presupuesto_categoria FOREIGN KEY (categoria_id) REFERENCES APP_SPRING_BOOT.categorias(id) ON DELETE CASCADE
);

CREATE TABLE APP_SPRING_BOOT.transacciones (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id NUMBER NOT NULL,
    categoria_id NUMBER NOT NULL,
    descripcion VARCHAR2(255) NOT NULL,
    monto BINARY_DOUBLE NOT NULL,
    tipo VARCHAR2(255) NOT NULL,
    fecha DATE NOT NULL,
    CONSTRAINT fk_transaccion_usuario FOREIGN KEY (user_id) REFERENCES APP_SPRING_BOOT.usuarios(id) ON DELETE CASCADE,
    CONSTRAINT fk_transaccion_categoria FOREIGN KEY (categoria_id) REFERENCES APP_SPRING_BOOT.categorias(id) ON DELETE CASCADE
);

CREATE TABLE APP_SPRING_BOOT.analisis_historial (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id NUMBER NOT NULL,
    ingreso_mensual NUMBER(12,2),
    nivel_endeudamiento NUMBER(5,2),
    frecuencia_ahorro VARCHAR2(20),
    perfil_resultado VARCHAR2(30),
    probabilidad NUMBER(5,4),
    fecha_analisis TIMESTAMP(6) DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_analisis_usuario FOREIGN KEY (user_id) REFERENCES APP_SPRING_BOOT.usuarios(id) ON DELETE CASCADE
);

CREATE TABLE APP_SPRING_BOOT.recomendaciones_historial (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    analisis_id NUMBER NOT NULL,
    recomendacion_texto CLOB NOT NULL,
    CONSTRAINT fk_recomendacion_analisis FOREIGN KEY (analisis_id) REFERENCES APP_SPRING_BOOT.analisis_historial(id) ON DELETE CASCADE
);

-- 
-- =============CREACIÓN DE ÍNDICES DE RENDIMIENTO===================
-- 


CREATE INDEX APP_SPRING_BOOT.idx_categoria_nombre ON APP_SPRING_BOOT.categorias(nombre);
CREATE INDEX APP_SPRING_BOOT.idx_usuarios_email ON APP_SPRING_BOOT.usuarios(email);
CREATE INDEX APP_SPRING_BOOT.idx_transacciones_user_fecha ON APP_SPRING_BOOT.transacciones(user_id, fecha);
CREATE INDEX APP_SPRING_BOOT.idx_presupuestos_user ON APP_SPRING_BOOT.presupuestos(user_id);
CREATE INDEX APP_SPRING_BOOT.idx_analisis_user_fecha ON APP_SPRING_BOOT.analisis_historial(user_id, fecha_analisis);
CREATE INDEX APP_SPRING_BOOT.idx_recomendaciones_analisis ON APP_SPRING_BOOT.recomendaciones_historial(analisis_id);

COMMIT;

```
